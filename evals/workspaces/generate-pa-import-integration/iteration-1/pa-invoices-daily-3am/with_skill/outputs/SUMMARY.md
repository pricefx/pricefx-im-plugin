## Caveats (verify before deploying)

1. **pfx CLI was not configured** for this run, so DMDS.Invoices metadata could not be fetched. The mapper uses **placeholder source column names** and a generic invoice-line-item attribute layout. Before deploying:
   - Run `pfx data-sources` to confirm the exact DMDS name. If different, update `dsUniqueName=DMDS.{name}` in the route plus `dataFeedName=DMF.{name}` and `dataSourceName=DMDS.{name}` in the flush.
   - Run `pfx data-source-metadata {name}` to get the real attribute labels/types, then re-map the `out="attribute*"` columns and confirm/adjust `converterExpression` per field.
   - Update the CSV source-column names (`in="..."`) in the mapper to match the real CSV header.
2. **Camel version assumption** — if target project is Camel 3 (IM ≤ 6.x), swap `aggregationStrategy=` for `strategyRef=` per docs/routes.md.
3. **Schedule semantics** — the quartz scheduler on the file URI does not fire once at 3am; it restricts polling to that minute. Cron `0 0 3 * * ?` fires at 03:00:00 UTC daily (single-minute window). For potentially late uploads, widen to e.g. `0 0 3-4 * * ?` for 03:00–04:59 UTC.
4. **businessKeys** — not set on pfx-api:loaddata. For DMDS this is normally fine because the data source defines its own keys; if needed, append `&businessKeys=sku` on the loaddata URI.
